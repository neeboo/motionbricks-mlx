# 0006 · 批量烘焙的"安全 B"规则（**提案，待人类批准**）

状态：**提案**，尚未批准。`docs/optimization-report.md` 第 23 节是它的证据；
`docs/decisions/` 里的决定由人类裁定，本轮只写提案。

**触发**：round 1 测到批量化的吞吐收益（pose 阶段 B=2/4/8 → 2.37×/3.12×/6.05×）但 B≥4 不逐位；
round 3 用真实 pipeline 重测了端到端烘焙，并做了 B=1/2/4/8/16 的 token 战役（第 23 节）。

**本轮实测（GPU，load 12.6–16.5，同进程交替配对，各 5 次取中位数）**：

| B | 串行 p50 | 批量 p50 | 加速 | 每场景（批量） | 吞吐 | token 逐位 |
|---|---|---|---|---|---|---|
| 1 | 27.79 ms | 29.25 ms | 0.950× | 29.25 ms | 34.19/s | 1/1 |
| 2 | 49.06 | 42.21 | 1.162× | 21.10 ms | 47.38/s | 2/2 |
| 4 | 103.82 | 108.04 | 0.961× | 27.01 ms | 37.02/s | 4/4 |
| 8 | 215.89 | 182.93 | 1.180× | 22.87 ms | 43.73/s | 8/8 |
| 16 | 426.56 | 345.99 | 1.233× | 21.62 ms | 46.24/s | 16/16 |
| 8（同 duration） | 219.18 | 159.15 | **1.377×** | 19.89 ms | 50.27/s | 8/8 |
| 16（同 duration） | 430.21 | 321.93 | **1.336×** | 20.12 ms | 49.70/s | 16/16 |

汇总：**31/31 场景 token 逐位一致，0/2136 个 token 决策不同，最终动作逐位相同**（roots/rotations 差
恰好 0）。原因是可量化的：批量相对串行的 logits 最大扰动 **3.357e-04**（B=16），而战役中最紧的一次
token 决策余量（Gumbel 加噪后 top1−top2）是 **2.985e-03**，**扰动 / 最紧余量 = 0.112×**（≈9× 安全系数）。

同时必须记住两点：**批量不是逐位**（`mx.vmap` 把每行 matmul 降成批量原语，B=1 就差 1.98e-04），
且**只批了 pose 阶段**——它只占一步的 ~23 %，所以端到端上限约 1.25×，实测 1.18–1.38× 已经到顶；
round 1 的 2.4–6.1× 是**阶段**吞吐，不是烘焙吞吐。

**提案（待批准）**：

1. **可复现烘焙档（reproducible bake tier）**＝本版本 `B` 的最大值，且该 `B` 下**批量产物中每个场景**
   都与**同一场景单独跑**在 `pose.tokens`、`pose.sampling_uniforms` 与**最终动作**上一致。
2. 就本轮证据，可复现档是 **`B ≤ 16`**（已测上限），安全系数 0.112×；更换 style/seed 组合或升级
   MLX 后**必须重跑战役**才继续算可复现档。
3. 超过可复现档、或本版本未重跑战役的任何 `B`，只能作**快速草稿档**，且**产物 manifest 必须记录
   批次大小 B 与战役结果**（哪一档、逐位率、最差偏差）。
4. 规则的判据是**离散 token 与最终动作**，不是浮点逐位。
5. **按 duration 分组**：同一 duration 组内加大 B 的收益高于跨 duration 混合（B=16 时 1.336× vs
   1.233×），且混合会产生每个 duration 一个编译变体。

**验收要求（若批准，落地时必须复跑）**：
1. `scripts/mlx_bench.py --bake <B 列表> --bake-repeats ≥5` 给出上表各列；
2. 每个 B 的逐场景 token/uniform/最终动作逐位率与最差偏差都写入报告；
3. manifest 里出现 `batch_size` 与 `bake_tier`（`reproducible` / `draft`）字段；
4. `pytest` 全绿且只增不减；`mlx_align plan/trace` 不回归。

**为什么不能只写"结论：B=8 安全"**：一致性是**数据相关**的——它取决于每个场景的决策余量。
本轮 2136 个决策里最紧的余量是 2.985e-03，比扰动大 9 倍，所以没翻；换一批 style 完全可能更紧。
因此规则必须是"**跑战役才给档位**"，而不是"某个 B 永久安全"。
