# 0010 · 安全裕度改按"逐场景"比较（并保留全局比值作为交叉核对）

**触发**：第 7 轮用**真实多样库**（8 种真实风格、24 帧同构）实测，`0008` 的机械规则把档位从 release 打到
**draft**：diverse B=8/B=16 的比值是 **1.4402 / 1.2716**（> 0.70）。他们**没有改判据、没有挑场景**，只报事实。

**诊断（关键）**：这个比值是 **跨场景相除**——分子（最大扰动）来自 `idle`（7.7e-03，是 `walk` 的 6 倍），
分母（最紧决策余量）来自 `walk_zombie`（2.99e-03，比 `idle` 的 3.6e-02 紧 12 倍）。
也就是说**拿 A 风格的扰动去比 B 风格的余量**；而**逐场景自己的比值最大只有 0.142**。
`idle` 单独烘反而是最安全的一档（0.2137）。

**裁定**：把判定统计量从"全局 max 扰动 ÷ 全局 min 余量"改为
**逐场景：该场景的扰动 ÷ 该场景自己的最紧决策余量，取所有场景的最大值**；阈值仍为 **≤ 0.70**。
**全局比值必须同时报告**（保持可比与可审计），但它不再是 tier 的唯一依据。

**为什么这不是放水，而是修正一个统计错误**：扰动与余量只有在**同一个决策**上比较才有意义；
把两个不同风格的极值相除，既可能虚高（本轮的 1.44），也可能虚低（掩盖真正的危险场景）。
新统计量对**每个场景**都设了上限，因此比旧的更贴近"哪里可能翻 token"。

**必须的证伪检验（做不到就不采纳）**：新统计量**必须**在已知不安全的那组上报警——
第 4/5 轮的 **混合 B=16**（全局比值 1.0426、零余量）其**逐场景最大比值必须 > 0.70**。
若它反而放过那组，则说明新统计量是错的，**本条裁定作废**，维持 `0008` 原文。

**沿用不变**：`B > 8` 必须时长同构；`B = 1` 永不用于烘焙；任何一次重跑中统计量越界即机械降档；
换模型/权重/指令分布必须重跑战役；manifest 需同时记 `bake_safety_ratio`（全局，向后可比）与
**新增逐场景字段**（例如 `bake_safety_ratio_per_scenario_max` 与各场景明细）。

**在证伪检验通过之前**：本轮 diverse 库保持 **draft**（不追认），release 档仍按 `0008` 的字面结论执行。
